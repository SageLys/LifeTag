# 1. 文档目的

本文档定义单局与单日玩法流程。v0.2 起，本文档不再把每日流程描述为玩家可见的网页式阶段推进，而是描述为：

```text
店铺主界面中的每日任务系统
+
功能区域点击触发
+
日结 / 收店奖励硬边界
```

本次改写废弃旧式：

```text
开店页 → 进货页 → 接单页 → 抽牌页 → 处理页 → 出售页 → 日结页 → 收店页
```

改为：

```text
玩家始终在一间肉铺中。
玩家点击公告牌、后门货源、订单板、牌盒、砧板、收银台、账本、保险柜等区域完成每日经营。
```

---

# 2. 单局总流程

单局仍为 8 天，胜负条件不变。

```text
NewRun
→ StartDay(day = 1)
→ ShopDayActive
→ ResolveDay
→ RewardPhase
→ StartDay(day + 1)
→ ...
→ EndRun
→ RunReport
```

第 1 天至第 8 天重复每日经营。第 8 天收店奖励完成后进入最终报告。

---

# 3. 每日流程新定义

每日不再要求玩家按固定顺序点击“进入进货 / 进入接单 / 进入抽牌”。每日由一组可在店铺中触发的任务构成。

## 3.1 每日可自由触发任务

```text
看新闻：点击公告牌。
进货：点击后门货源 / 冷柜货源区。
接单：点击柜台订单板。
抽牌：点击牌盒 / 抽屉。
查看库存：点击冷柜 / 肉架。
加工：点击砧板。
出售：点击收银台。
查看被动：点击保险柜 / 店铺状态。
查看日志：点击账本侧栏或日志抽屉。
```

这些任务没有强制顺序。玩家可以先抽牌，再看订单；也可以先看订单，再进货；也可以先看新闻，再处理库存旧货。

## 3.2 每日硬边界

以下流程仍有硬边界：

```text
日结：点击账本，确认后锁定当天经营。
收店奖励：日结后出现，完成后进入下一天。
最终报告：第 8 天收店后出现。
失败报告：现金 < 0 或信誉 <= 0 时出现。
```

日结后，当天不得继续：

```text
进货
抽牌
加工
出售
```

# 4. 内部状态模型

## 4.1 RunPhase 的新职责

`RunPhase` 可以暂时保留用于兼容、Debug、最终报告与失败状态，但不再作为玩家可见主导航。

推荐长期目标：

```text
RUN_INIT
SHOP_DAY_ACTIVE
DAY_RESOLVED
DAY_REWARD
RUN_END
RUN_FAILED
```

短期可以继续保留旧枚举，但正式 UI 不得再用 `DAY_PURCHASE`、`DAY_CUSTOMER`、`DAY_DRAW` 等阶段决定主屏幕。

## 4.2 DayState.taskFlags

新增或等价迁移：

```ts
dayState.taskFlags = {
  marketGenerated: false,
  marketRead: false,
  productCandidatesGenerated: false,
  customerOrdersGenerated: false,
  cardsDrawnToday: false,
  processingOpened: false,
  dayResolved: false,
  rewardGenerated: false,
  rewardChosen: false,
};
```

现有 `phaseFlags.drawnToday` 等字段可以短期兼容，但后续应迁移到 `taskFlags`。

## 4.3 UIState.activeShopArea

新增：

```ts
uiState.activeShopArea = null | 'news' | 'supply' | 'orders' | 'deck' | 'inventory' | 'process' | 'cashier' | 'daybook' | 'reward' | 'passives';
```

UI 的当前打开区域由 `activeShopArea` 决定，而不是由 `DayState.phase` 决定。

# 5. 功能触发规则

## 5.1 新闻

点击公告牌：

```text
如果今日新闻未生成：生成新闻。
标记 marketRead = true。
打开新闻详情。
重复点击不得重刷新闻。
```

## 5.2 进货

点击后门货源：

```text
如果商品候选未生成：生成今日商品候选。
打开进货面板。
买入仍受现金、库存上限、每日进货上限限制。
重复点击不得重刷商品候选。
```

## 5.3 接单

点击订单板：

```text
如果顾客订单未生成：生成今日顾客订单。
打开订单面板。
玩家可以选择顾客用于交易预览。
重复点击不得重刷顾客订单。
```

## 5.4 抽牌

点击牌盒：

```text
如果今日未抽牌：抽取今日手牌。
如果已抽牌：只查看手牌、抽牌堆、弃牌堆。
重复点击不得重复抽牌。
```

## 5.5 加工

点击砧板：

```text
打开加工面板。
显示库存商品、商品详情、基础操作、手牌。
没有库存时显示空状态。
行动点不足、现金不足、目标非法时按钮 disabled 并显示原因。
```

## 5.6 出售

点击收银台：

```text
打开出售面板。
需要商品、顾客、定价方式和有效交易预览才能确认出售。
如果缺少顾客订单，可提示点击订单板。
如果缺少库存，可提示点击进货区或库存区。
```

## 5.7 日结

点击账本：

```text
显示今日摘要。
如果今日未出售，二次确认。
确认后执行日结，dayResolved = true。
日结后锁定当天经营操作。
```

## 5.8 收店奖励

点击保险柜：

```text
必须 dayResolved = true。
生成并显示收店奖励。
现金不足的奖励不可选。
完成奖励后进入下一天或最终报告。
```

---

# 6. 异常处理

必须避免玩家因为自由顺序而卡死。

```text
没有新闻：使用默认新闻。
没有商品候选：点击进货区时生成。
没有顾客订单：点击订单板时生成。
没有手牌：点击牌盒时抽牌。
没有库存：砧板和收银台显示空状态，不报错。
未选择商品 / 顾客 / 定价：交易预览显示缺失项。
日结后点击经营区：显示“今日已日结，明天再处理”。
```

---

# 7. 验收标准

```text
1. 玩家进入第 1 天后看到店铺主界面，而不是开店阶段页面。
2. 新闻、进货、接单、抽牌可以任意顺序触发。
3. 同一日内新闻、商品、顾客、抽牌不会因重复点击而重复生成。
4. 砧板、收银台可以随时打开，但按钮按资源与选择状态 disabled。
5. 交易预览根据商品、顾客、定价即时刷新。
6. 日结是每日硬边界。
7. 收店奖励只在日结后出现。
8. 第 8 天收店后进入最终报告。
9. 现金、累计利润、信誉、事故、隐藏标签、暗风险规则不变。
10. Debug 面板与固定测试局继续可用。
```
