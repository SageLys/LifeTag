# 风险模型配置修改明细 v3

## 0. 修改目标

当前风险模型的问题是：商品购入时已经固定了大量风险，出售时顾客选择对风险区间影响不足。

本次配置修改目标：

1. 商品 `baseRisk` 只表示“货源脏度”，不能单独决定事故等级。
2. 同一商品卖给不同顾客时，风险区间必须不同。
3. 隐藏标签、暗风险在预览阶段也必须按当前顾客动态计算。
4. 标签工具牌必须真正添加 `appliedTagIds`，不能只加售价。
5. 顾客配置要表达“审查逻辑”，不只表达“喜欢什么 / 讨厌什么”。
6. 卡牌、市场新闻、被动的条件修正必须可被程序读取和过滤。

# 3. data/customers.json 修改

## 3.1 新增字段：customerRiskProfile

给每个顾客新增：

```json
"customerRiskProfile": {
  "riskTraitBonus": {},
  "darkRiskCategoryMultiplier": {},
  "pricingRiskMultiplier": {},
  "fitRiskReduction": {
    "enabled": true,
    "minPreferredHits": 2,
    "perHit": 3,
    "max": 10
  },
  "toleranceMargin": 15,
  "overToleranceAccidentLevelAdd": 1
}
```

字段含义：

| 字段                          | 说明                                    |
| ----------------------------- | --------------------------------------- |
| riskTraitBonus                | 顾客对某类风险特征的审查强度            |
| darkRiskCategoryMultiplier    | 暗风险类别敏感倍率                      |
| pricingRiskMultiplier         | 当前顾客对定价风险的放大/缩小           |
| fitRiskReduction              | 高适配顾客的风险减免                    |
| toleranceMargin               | 超过 `riskTolerance` 多少后触发容忍惩罚 |
| overToleranceAccidentLevelAdd | 超过容忍后事故等级增加值                |

# 4. data/darkRisks.json 修改

## 4.1 修改原则

暗风险本身保留 `riskMin/riskMax/actualRiskDefault`，但风险预览必须按顾客敏感倍率计算：

```text
预览暗风险区间 =
darkRisk.riskMin/riskMax × customerRiskProfile.darkRiskCategoryMultiplier[darkRisk.category]
```

结算暗风险：

```text
actualRisk =
darkRisk.actualRiskDefault × customerRiskProfile.darkRiskCategoryMultiplier[darkRisk.category]
```

# 10. data/marketEvents.json 修改原则

## 10.1 原则

市场新闻不能无条件给某类标签加风险。

错误示例：

```text
[会发疯] 风险 +20
```

正确示例：

```text
[会发疯] 卖给 family 顾客时风险 +20
platform 暗风险卖给 MCN 时风险 +25
```

## 10.2 需要统一的条件

所有风险 modifier 必须有明确条件：

```json
"condition": {
  "type": "customer_type_is",
  "params": {
    "customerType": "family"
  }
}
```

或：

```json
"condition": {
  "type": "all",
  "conditions": [
    {
      "type": "product_has_tag",
      "params": {
        "tagId": "tag_crazy"
      }
    },
    {
      "type": "customer_type_is",
      "params": {
        "customerType": "family"
      }
    }
  ]
}
```

## 10.3 重点新闻调整

### 发疯文学爆火

- [会发疯] / [抽象] 对 MCN 加价。
- 卖给 family 顾客才增加风险。
- 不要对所有顾客无条件加风险。

### 名校水货事件发酵

- [名校] 加价。
- [水货] 只在 career/family 顾客处显著加风险。
- career_background 暗风险只在 career/family 顾客处放大。

### 短视频平台严查塌房人设

- MCN 加价仍可保留。
- platform 暗风险卖给 MCN 时显著加风险。
- 非 MCN 顾客只给残余风险或不加。

# 13. 最终验收标准

1. 同一商品卖给不同顾客，`riskMin/riskMax` 经常不同。
2. 未揭示暗风险在预览阶段就按顾客敏感度变化。
3. 标签工具牌会真正添加 appliedTag。
4. 条件 modifier 只在条件满足时进入 priceBreakdown / riskBreakdown。
5. 商品 `baseRisk` 不再单独决定事故等级。
6. 事故链条能解释：顾客、雷区、包装、暗风险、定价分别贡献了什么风险。
