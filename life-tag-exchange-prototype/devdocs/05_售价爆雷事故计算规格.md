文档编号：05

项目名称：《人生标签交易所：牛马肉铺》HTML 快速验证原型  
对应策划案版本：核心策划案 v0.5

# 1. 文档目的

本文档用于回答以下问题：

1. 交易预览中的预计售价怎么计算；
    
2. 交易预览中的爆雷值或爆雷区间怎么计算；
    
3. 未揭示隐藏标签和暗风险如何进入预览；
    
4. 出售确认后如何计算最终售价；
    
5. 出售确认后如何计算最终爆雷；
    
6. 事故等级如何判定；
    
7. 事故等级如何被顾客、市场新闻、卡牌、店铺被动和盲盒价修正；
    
8. 事故后果如何结算退款、罚款、信誉损失；
    
9. 现金和累计利润如何分别变化；
    
10. 事故链条如何生成，确保玩家能复盘。
    

本文档不负责：

- 定义 UI 布局；
    
- 定义全部卡牌文案；
    
- 定义最终平衡数值；
    
- 定义正式版 Unity 架构；
    
- 定义长期运营数值。
    

本文档负责：

```text
把“这单为什么贵、为什么炸、炸了扣什么”固定成程序可执行的计算顺序。
```

# 2. 计算核心原则

## 2.1 事故不随机

本游戏允许随机生成：

```text
商品候选
隐藏标签
暗风险
顾客订单
市场新闻
抽牌结果
收店奖励
```

但不允许随机决定：

```text
事故是否发生
```

事故是否发生只由最终爆雷值和事故等级修正规则决定。

## 2.2 预览可以不精确，但必须诚实

如果商品没有未知信息，交易预览显示精确爆雷值。

如果商品存在未揭示隐藏标签或未完全处理暗风险，交易预览显示爆雷区间。

```text
预览不需要告诉玩家隐藏标签是什么。
预览必须告诉玩家这单最安全和最危险可能到什么程度。
```

## 2.3 结算必须使用真实数据

出售确认后，系统使用 ProductInstance 中真实存在的：

```text
真实显性标签
真实隐藏标签
真实暗风险
已添加包装标签
已压制标签
临时修正
顾客规则
市场新闻
卡牌效果
店铺被动
定价方式
```

计算最终售价、最终爆雷和事故。

## 2.4 售价与爆雷必须可拆解

每个价格来源、风险来源、事故修正来源都必须进入 breakdown。

交易预览输出：

```text
priceBreakdown
riskBreakdown
unknownRiskBreakdown
warnings
```

交易结算输出：

```text
priceBreakdown
riskBreakdown
accidentChain
cashDeltaBreakdown
profitBreakdown
reputationBreakdown
```

## 2.5 现金与累计利润分离

现金 `cash` 是当前资源。

累计利润 `totalProfit` 是通关目标。

商品进价在进货时已经扣现金。

出售结算时：

```text
cash += finalPrice
cash -= refund
cash -= fine
```

累计利润结算时：

```text
singleProfit = finalPrice - product.cost - refund - fine
totalProfit += max(0, singleProfit)
```

除非特殊规则明确写出 `totalProfitBonus`，否则洗标、包装、公关、卡牌、奖励成本都不影响累计利润。

# 4. 计算时机

## 4.1 交易预览计算时机

以下任一事件发生后，必须重新计算交易预览：

```text
选中商品变化
选中顾客变化
选中定价方式变化
商品标签变化
隐藏标签揭示
暗风险揭示程度变化
商品被洗标
商品被包装
商品被公关
卡牌作用于商品
卡牌作用于交易
市场新闻变化
店铺被动变化
货源倾向影响商品属性
行动点或现金变化导致操作可用性变化
```

## 4.2 交易结算计算时机

玩家点击：

```text
确认出售
```

后执行最终计算。

结算时必须锁定：

```text
selectedProduct
selectedCustomer
selectedPricingMode
activeMarketEvent
playedCardEffects
activePassives
temporaryModifiers
```

锁定后，即使 UI 后续变化，也不影响本次 DealResult。

# 5. 计算上下文 CalculationContext

所有计算函数建议接收统一上下文。

```text
CalculationContext {
  mode: "preview" | "resolve",

  runState,
  dayState,

  product,
  customerOrder,
  customerDef,
  pricingMode,
  marketEvent,

  activePassives,
  activeSupplySources,

  productModifiers,
  dealModifiers,
  customerModifiers,
  globalModifiers,
  accidentModifiers,

  configTables
}
```

## 5.1 mode = preview

用于交易预览。

特点：

```text
隐藏标签未揭示时，不显示具体标签。
暗风险未完全揭示时，不显示具体暗风险。
风险可以显示区间。
不会修改 RunState。
不会修改 ProductInstance。
不会生成 DealResult。
```

## 5.2 mode = resolve

用于确认出售后的真实结算。

特点：

```text
使用真实隐藏标签。
使用真实暗风险。
计算最终风险。
确定事故等级。
修改 cash / totalProfit / reputation。
标记商品已售出。
生成 DealResult 和 AccidentInstance。
```

# 6. 标签参与计算规则

## 6.1 标签来源分类

商品标签来源包括：

|来源|说明|是否真实|是否可见|是否参与售价|是否参与风险|
|---|---|---|---|---|---|
|true_visible|显性真实标签|是|初始可见|是|是|
|true_hidden_revealed|已揭示隐藏真实标签|是|鉴定后可见|是|是|
|true_hidden_unrevealed|未揭示隐藏真实标签|是|不可见|不参与已知售价；参与风险区间|参与未知风险区间|
|applied|包装标签 / 卡牌添加标签|否或表层|可见|是|是|
|temporary|临时标签 / 临时效果|视规则|可见或隐藏|视规则|视规则|
|suppressed|被压制标签|真实存在但被处理|可显示为已压制|默认不贡献售价|保留残余风险|

## 6.2 有效已知标签 effectiveKnownTags

用于预览中的已知售价、已知风险。

包括：

```text
true_visible
true_hidden_revealed
applied
temporary 可见标签
```

不包括：

```text
true_hidden_unrevealed
```

## 6.3 结算真实标签 effectiveResolvedTags

用于最终结算。

包括：

```text
true_visible
true_hidden_revealed
true_hidden_unrevealed
applied
temporary 仍然有效的标签
```

## 6.4 被压制标签 suppressedTags

洗标或卡牌不会删除真实标签，而是把标签标记为 suppressed。

默认规则：

|项目|处理方式|
|---|---|
|标签 basePrice|按 0 计算|
|顾客 preference priceBonus|按 0 计算|
|标签 baseRisk|按 30% 计算，四舍五入|
|顾客 taboo riskBonus|按 30% 计算，四舍五入|
|市场新闻对该标签的 riskModifier|按 30% 计算，四舍五入|
|标签冲突 riskAdd|若冲突由该标签引起，按 30% 计算|
|事故链条|仍显示，但标注“已压制”|

示例：

```text
[水货] baseRisk = 30
被洗标后：
risk = round(30 × 0.3) = 9
```

## 6.5 重复标签去重规则

同一 tagId 可能来自真实标签和包装标签。

默认处理：

```text
标签 basePrice、baseRisk、顾客偏好、顾客雷区按 tagId 去重计算一次。
卡牌自身附带的 add_price / add_risk modifier 可以额外叠加。
```

示例：

```text
商品真实拥有 [名校]
又使用【名校背书】添加 [名校] 类包装

[名校] 标签 basePrice 只计算一次。
【名校背书】卡牌自身的售价 +35 仍然额外计算。
如果卡牌有“已有 [名校] 时额外 +15”，也额外计算。
```

# 7. 售价计算总流程

## 7.1 售价计算函数

建议函数名：

```text
calculatePrice(context)
```

输入：

```text
product
customer
pricingMode
marketEvent
activePassives
modifiers
mode
```

输出：

```text
{
  rawPrice,
  multiplier,
  priceBeforeBudgetCap,
  effectiveBudget,
  finalPrice,
  priceBreakdown
}
```

## 7.2 售价计算顺序

售价按以下顺序计算：

```text
1. 读取 product.basePrice
2. 计算有效预算 effectiveBudget
3. 收集有效已知标签 effectiveKnownTags
4. 计算标签基础价格 tagBasePrice
5. 计算顾客偏好价格 customerPreferencePrice
6. 计算标签冲突 / 支撑的价格修正 tagRelationPrice
7. 计算市场新闻价格修正 marketPriceModifier
8. 计算商品新鲜度价格修正 freshnessPriceModifier
9. 计算卡牌、基础操作、被动、货源等加法价格修正 additivePriceModifiers
10. 得到 rawPrice
11. 计算包装倍率 packageMultiplier
12. 计算定价倍率 pricingMultiplier
13. 计算被动 / 卡牌 / 新闻等乘法倍率 otherMultipliers
14. 得到 priceBeforeBudgetCap
15. 应用预算上限
16. 得到 finalPrice
17. 生成 priceBreakdown
```

# 8. 售价详细规则

## 8.1 基础价

```text
rawPrice = product.basePrice
```

breakdown：

```text
基础价：+product.basePrice
```

## 8.2 标签基础价格

对 effectiveKnownTags 中每个未被压制标签：

```text
rawPrice += tag.basePrice
```

如果 tag.basePrice 为负数，也正常计算。

示例：

```text
[名校] basePrice +20
[水货] basePrice -10
```

未揭示隐藏标签不参与当前售价计算。

原因：

```text
玩家没有鉴定出来的隐藏卖点，默认不能主动拿来加价。
```

例外：

```text
盲盒价
特定卡牌
特定被动
```

可以通过额外规则把未知信息转化为收益。

## 8.3 顾客偏好价格

如果商品有效标签命中顾客 preferredTags：

```text
rawPrice += preference.priceBonus
```

规则：

```text
同一个顾客偏好标签只计算一次。
被压制标签不触发顾客偏好。
未揭示隐藏标签不触发顾客偏好。
applied 标签可以触发顾客偏好。
```

示例：

```text
商品有 [年轻] [名校]
卖给大厂 HR：
[年轻] preference +20
[名校] preference +25
```

## 8.4 标签支撑 / 冲突价格修正

读取 tagConflicts。

如果关系为 support：

```text
rawPrice += priceAdd
```

如果关系为 conflict：

```text
rawPrice += priceAdd
```

注意：

```text
conflict 的 priceAdd 通常为负数。
support 的 priceAdd 通常为正数。
```

默认只对 effectiveKnownTags 生效。

如果冲突涉及未揭示隐藏标签：

```text
在预览阶段不加入 rawPrice；
在结算阶段也不改变 finalPrice，除非该隐藏标签已在出售前揭示。
```

原因：

```text
隐藏标签主要影响风险，不默认影响成交价。
```

## 8.5 市场新闻价格修正

市场新闻 modifier 满足条件时：

```text
rawPrice += modifier.value
```

示例：

```text
今日新闻：名校水货事件发酵
如果商品有 [名校]：
rawPrice += 20
```

要求：

```text
市场新闻价格修正必须进入 priceBreakdown。
```

## 8.6 新鲜度价格修正

如果商品腐败：

```text
rawPrice += GameConfig.spoiledPriceAdd
```

默认：

```text
spoiledPriceAdd = -20
```

如果未腐败：

```text
无修正
```

## 8.7 加法价格 modifier

以下来源可以提供加法价格：

```text
卡牌
基础操作
店铺被动
货源倾向
市场新闻
特殊顾客规则
```

统一处理：

```text
if modifier.stat == "price" and condition pass:
  rawPrice += modifier.value
```

## 8.8 rawPrice 下限

倍率计算前：

```text
rawPrice = max(1, rawPrice)
```

## 8.9 包装倍率

基础操作【包装】默认添加：

```text
priceMultiplier ×1.2
risk +10
```

如果商品已基础包装：

```text
packageMultiplier = 1.2
```

否则：

```text
packageMultiplier = 1.0
```

若卡牌或被动另有包装倍率，作为 otherMultipliers 处理。

## 8.10 定价倍率

|定价方式|priceMultiplier|
|---|--:|
|pricing_cheap|0.8|
|pricing_normal|1.0|
|pricing_high|1.3|
|pricing_blind_box|1.45|

计算：

```text
pricingMultiplier = selectedPricingMode.priceMultiplier
```

## 8.11 其他倍率

卡牌、被动、新闻可以提供乘法倍率：

```text
otherMultipliers = product of all active priceMultiplier modifiers
```

例如：

```text
某被动：职场商品售价 ×1.1
某卡牌：本单售价 ×1.2
```

则：

```text
otherMultipliers = 1.1 × 1.2 = 1.32
```

## 8.12 预算上限

先计算：

```text
priceBeforeBudgetCap =
round(rawPrice × packageMultiplier × pricingMultiplier × otherMultipliers)
```

然后：

```text
finalPrice = min(priceBeforeBudgetCap, effectiveBudget)
```

默认所有顾客有预算上限。

如果特殊规则允许突破预算，必须明确写出：

```text
ignoreBudgetCap = true
```

第一版默认不启用突破预算。

## 8.13 最终价格下限

最终价格不得低于 1。

```text
finalPrice = max(1, finalPrice)
```

# 9. 有效预算 effectiveBudget

## 9.1 基础预算

```text
effectiveBudget = customerOrder.budget
```

## 9.2 顾客临时预算修正

市场新闻、被动、事故历史可以修改顾客预算。

```text
effectiveBudget += budgetAddModifiers
```

```text
effectiveBudget = max(1, round(effectiveBudget))
```

```text

  visibleToPlayer: true

```

示例：

```text
基础价：+50

[名校]：+20
```

# 11. 爆雷计算总流程

## 11.1 爆雷计算函数

建议函数名：

```text
calculateRisk(context)
```

输出：

```text
{
  riskDisplayType,
  knownRisk,
  unknownHiddenRiskMin,
  unknownHiddenRiskMax,
  unknownDarkRiskMin,
  unknownDarkRiskMax,
  riskMin,
  riskMax,
  exactRisk,
  riskBreakdown,
  unknownRiskBreakdown,
  warnings
}
```

## 11.2 爆雷计算顺序

```text
1. 读取 product.baseRisk
2. 收集 effectiveKnownTags
3. 计算已知标签风险 knownTagRisk
4. 计算顾客雷区风险 customerTabooRisk
5. 计算标签冲突风险 tagConflictRisk
6. 计算虚假包装风险 fakePackageRisk
7. 计算市场新闻风险 marketRisk
8. 计算新鲜度风险 freshnessRisk
9. 计算定价风险 pricingRisk
10. 计算卡牌 / 基础操作 / 被动 / 货源已知风险修正 knownModifierRisk
11. 计算公关、转嫁、暗风险处理等风险减免
12. 得到 knownRisk
13. 计算未揭示隐藏标签风险区间
14. 计算未完全揭示暗风险区间
15. 得到 riskMin / riskMax 或 exactRisk
16. 生成 riskBreakdown 与 unknownRiskBreakdown
```

# 12. 已知风险 knownRisk

## 12.1 基础风险

```text
knownRisk = product.baseRisk
```

breakdown：

```text
商品基础风险：+product.baseRisk
```

## 12.2 已知标签基础风险

对 effectiveKnownTags 中每个标签：

```text
knownRisk += tag.baseRisk
```

如果标签被 suppressed：

```text
knownRisk += round(tag.baseRisk × 0.3)
```

## 12.3 顾客雷区风险

如果商品有效标签命中顾客 tabooTags：

```text
knownRisk += taboo.riskBonus
```

如果该标签被 suppressed：

```text
knownRisk += round(taboo.riskBonus × 0.3)
```

规则：

```text
applied 标签可以命中顾客雷区。
true_visible 标签可以命中顾客雷区。
true_hidden_revealed 标签可以命中顾客雷区。
true_hidden_unrevealed 在预览中进入未知风险，在结算中进入最终风险。
```

## 12.4 标签冲突风险

读取 tagConflicts。

如果商品有效标签同时包含 tagA 和 tagB：

```text
knownRisk += conflict.riskAdd
```

如果其中一个标签被 suppressed：

```text
knownRisk += round(conflict.riskAdd × 0.3)
```

如果两个标签都被 suppressed：

```text
knownRisk += round(conflict.riskAdd × 0.1)
```

## 12.5 支撑关系风险修正

如果 relation = support：

```text
knownRisk += support.riskAdd
```

support.riskAdd 可以为负数。

示例：

```text
[稳定] + [情绪稳定]：risk -5
```

## 12.6 虚假包装风险 fakePackageRisk

当 applied 标签与真实标签形成冲突时，视为虚假包装风险。

基础规则：

```text
如果 applied 标签和 true 标签之间存在 conflict：
  knownRisk += conflict.riskAdd
```

如果 true 标签未揭示：

```text
预览阶段进入 unknownHiddenRiskMax。
结算阶段进入 finalRisk。
```

示例：

```text
真实隐藏标签：[水货]
applied：[名校]
冲突：[名校] + [水货] risk +35
```

未揭示时：

```text
风险区间上限增加。
```

揭示或结算时：

```text
最终风险增加。
```

## 12.7 市场新闻风险

市场新闻风险 modifier 满足条件时：

```text
knownRisk += modifier.value
```

如果 modifier 作用于未揭示隐藏标签：

```text
预览阶段进入 unknownRiskBreakdown。
结算阶段进入 finalRisk。
```

## 12.8 新鲜度风险

如果商品腐败：

```text
knownRisk += GameConfig.spoiledRiskAdd
```

默认：

```text
spoiledRiskAdd = +20
```

## 12.9 定价风险

|定价方式|riskAdd|
|---|--:|
|pricing_cheap|-10|
|pricing_normal|0|
|pricing_high|+15|
|pricing_blind_box|+20|

计算：

```text
knownRisk += pricingMode.riskAdd
```

## 12.10 卡牌与基础操作风险修正

所有 active modifier 中：

```text
if modifier.stat == "risk" and condition pass:
  knownRisk += modifier.value
```

风险减免本质上也是 risk add，只是 value 为负数。

示例：

```text
试用期转嫁：risk -20
公关：risk -20
深度背调命中履历风险：risk -10
热搜预热：risk +15
```

## 12.11 店铺被动风险修正

被动在以下时机可能影响风险：

```text
onBeforeDealPreview
onBeforeDealResolve
```

所有满足条件的被动 risk modifier 加入 knownRisk。

要求：

```text
被动来源必须进入 riskBreakdown。
```

# 13. 未揭示隐藏标签风险区间

## 13.1 何时存在 unknownHiddenRisk

如果 ProductInstance 存在：

```text
tagEntry.source == true_hidden
tagEntry.revealed == false
```

则存在未揭示隐藏标签风险。

## 13.2 预览阶段处理

未揭示隐藏标签在预览中不显示具体 tagId。

但程序可以使用真实 hiddenTag 数据计算风险区间。

默认规则：

```text
unknownHiddenRiskMin += 0
unknownHiddenRiskMax += hiddenTagPotentialRisk
```

其中：

```text
hiddenTagPotentialRisk =
tag.baseRisk
+ customerTabooRiskIfHit
+ marketRiskIfAffected
+ conflictRiskIfConflictWithKnownOrAppliedTags
```

如果 hiddenTagPotentialRisk 小于 0：

```text
unknownHiddenRiskMax += 0
```

原因：

```text
风险区间用于提示坏情况。
未揭示正面标签不默认降低风险下限。
```

## 13.3 结算阶段处理

出售确认后：

```text
finalRisk += actualHiddenTagRisk
```

actualHiddenTagRisk 包括：

```text
hiddenTag.baseRisk
+ 顾客雷区
+ 市场新闻
+ 标签冲突
+ 虚假包装冲突
```

## 13.4 未揭示隐藏标签是否影响售价

默认不影响售价。

原因：

```text
未揭示标签没有被玩家拿出来包装或定价，不应该自动加价。
```

例外：

```text
pricing_blind_box
特定卡牌
特定被动
```

# 14. 暗风险区间

## 14.1 暗风险字段

ProductInstance.darkRisk 包含：

```text
exists
category
revealedLevel
darkRiskId
actualRiskValue
```

revealedLevel 可为：

```text
unknown
existence_only
category
full
treated
```

## 14.2 没有暗风险

如果：

```text
darkRisk.exists == false
```

则：

```text
unknownDarkRiskMin = 0
unknownDarkRiskMax = 0
```

## 14.3 unknown / existence_only

如果暗风险存在，但没有揭示类别：

```text
revealedLevel == unknown
或
revealedLevel == existence_only
```

预览显示：

```text
暗风险：存在
```

计算：

```text
unknownDarkRiskMin += darkRiskDef.riskMin
unknownDarkRiskMax += darkRiskDef.riskMax
```

如果顾客对该暗风险类别敏感：

```text
unknownDarkRiskMax += GameConfig.darkRiskSensitivityBonus
```

第一版建议：

```text
darkRiskSensitivityBonus = 15
```

如果 category 不应暴露给玩家，UI 只显示：

```text
暗风险存在，可能导致事故升级。
```

## 14.4 category

如果暗风险类别已揭示：

```text
revealedLevel == category
```

预览显示：

```text
暗风险：履历类 / 人设类 / 平台类
```

计算：

```text
unknownDarkRiskMin += darkRiskDef.riskMin
unknownDarkRiskMax += darkRiskDef.riskMax
```

如果顾客敏感：

```text
unknownDarkRiskMin += 5
unknownDarkRiskMax += 15
```

说明：

```text
类别已知后，风险区间仍存在，但玩家知道是哪类风险。
```

## 14.5 full

如果暗风险完全揭示：

```text
revealedLevel == full
```

计算：

```text
knownRisk += darkRisk.actualRiskValue
```

如果顾客敏感：

```text
knownRisk += 15
```

预览显示精确值。

## 14.6 treated

如果暗风险被处理：

```text
revealedLevel == treated
```

默认计算：

```text
knownRisk += round(darkRisk.actualRiskValue × 0.3)
```

如果卡牌或被动指定具体处理值，则使用指定值。

示例：

```text
平台对冲：平台暗风险 risk -25
```

可以在暗风险本体计算后作为 modifier 继续扣除。

# 15. 风险区间输出

## 15.1 没有未知信息

如果：

```text
unknownHiddenRiskMax == 0
且
unknownDarkRiskMax == 0
```

则：

```text
riskDisplayType = exact
exactRisk = clampRisk(knownRisk)
riskMin = exactRisk
riskMax = exactRisk
```

## 15.2 存在未知信息

如果存在未揭示隐藏标签或未完全揭示暗风险：

```text
riskDisplayType = range
riskMin = clampRisk(knownRisk + unknownHiddenRiskMin + unknownDarkRiskMin)
riskMax = clampRisk(knownRisk + unknownHiddenRiskMax + unknownDarkRiskMax)
exactRisk = null
```

## 15.3 clampRisk

风险下限为 0。

```text
risk = max(0, round(risk))
```

风险无硬上限。

事故 severe 从 100 开始。

```text
getAccidentLevel(risk)
```

```text
accidentPrediction = getAccidentLevel(exactRisk)
```

# 17. 最终风险 finalRisk

## 17.1 结算阶段 finalRisk

出售确认后：

```text
finalRisk =
knownRisk
+ actualHiddenRisk
+ actualDarkRisk
```

其中 knownRisk 在 resolve 模式下重新计算，不能直接复用 preview 结果。

## 17.2 actualHiddenRisk

对所有真实隐藏标签，无论是否已揭示：

```text
actualHiddenRisk += hiddenTag.baseRisk
actualHiddenRisk += customerTabooRiskIfHit
actualHiddenRisk += marketRiskIfAffected
actualHiddenRisk += conflictRiskIfConflict
```

如果隐藏标签已被压制：

```text
相关风险按 30% 计算。
```

## 17.3 actualDarkRisk

根据 darkRisk.revealedLevel：

|revealedLevel|finalRisk 处理|
|---|---|
|unknown|加 actualRiskValue|
|existence_only|加 actualRiskValue|
|category|加 actualRiskValue|
|full|加 actualRiskValue|
|treated|加 round(actualRiskValue × 0.3)，再应用处理 modifier|

如果顾客敏感：

```text
actualDarkRisk += 15
```

## 17.4 finalRisk 下限

```text
finalRisk = max(0, round(finalRisk))
```

# 18. 事故等级修正顺序

## 18.1 基础事故等级

```text
baseAccidentLevel = getAccidentLevel(finalRisk)
```

## 18.2 等级修正顺序

事故等级必须按以下顺序修正：

```text
1. 根据 finalRisk 得到基础事故等级
2. 应用顾客特殊规则
3. 应用市场新闻特殊规则
4. 应用卡牌特殊规则
5. 应用店铺被动特殊规则
6. 应用盲盒价特殊规则
7. 限制事故等级在 none ~ severe 之间
```

## 18.3 等级数值映射

内部可将事故等级映射为数值：

|level|value|
|---|--:|
|none|0|
|minor|1|
|medium|2|
|major|3|
|severe|4|

修正：

```text
levelValue += modifier.value
levelValue = clamp(levelValue, 0, 4)
```

最后转回事故等级。

## 18.4 顾客特殊规则示例

大厂 HR：

```text
如果 finalRisk > customer.riskTolerance：
  accidentLevel +1
```

家长委员会：

```text
不直接提高事故等级。
但 medium 以上事故会额外增加信誉损失。
```

## 18.5 市场新闻特殊规则示例

名校水货事件发酵：

```text
如果商品同时有 [名校] 和 [水货]：
  accidentLevel +1
```

发疯文学爆火：

```text
如果卖给家长委员会且商品有 [会发疯] 或 [抽象]：
  accidentLevel +1
```

## 18.6 卡牌特殊规则示例

封口包装：

```text
本单事故等级 +1
```

黑红预案：

```text
卖给 MCN 时，小事故不扣信誉，转化为 heat +1
```

注意：

```text
黑红预案默认不改变事故等级，只改变事故后果。
```

## 18.7 店铺被动特殊规则示例

舆论止损预案：

```text
每局第一次 severe 事故降为 major，但 cash -50。
```

黑红也是红：

```text
卖给 MCN 时，minor 事故不扣信誉，转化为 heat +2。
如果 major 或 severe，heat 清零，reputationLoss +10。
```

## 18.8 盲盒价特殊规则

如果 selectedPricingMode = pricing_blind_box：

```text
如果出售确认时仍存在未揭示信息：
  检查 unknownInfoHitCustomerTaboo
```

### 未知信息命中顾客雷区

满足任一条件：

```text
出售前未揭示的 hiddenTag 命中 customer.tabooTags
未完全处理的 darkRisk.category 命中 customer.darkRiskSensitivity
```

则：

```text
accidentLevel +1
```

### 未知信息未命中顾客雷区

如果没有命中：

```text
totalProfitBonus += 20
```

注意：

```text
该 +20 是累计利润奖励，不默认增加现金。
```

# 19. 事故后果计算

## 19.1 事故后果函数

建议函数名：

```text
calculateAccidentOutcome(context, finalPrice, finalRisk, finalAccidentLevel)
```

输出：

```text
{
  refundRate,
  refund,
  fine,
  reputationLoss,
  cashDelta,
  reputationDelta,
  outcomeBreakdown
}
```

## 19.2 基础事故后果

从 AccidentDef 读取：

|level|refundRate|fine|reputationLoss|
|---|--:|--:|--:|
|none|0|0|0|
|minor|0.1|0|5|
|medium|0.3|0|15|
|major|0.5|10|30|
|severe|0.8|30|45|

## 19.3 后果修正顺序

事故后果按以下顺序修正：

```text
1. 读取 AccidentDef 基础 refundRate / fine / reputationLoss
2. 应用顾客后果修正
3. 应用市场新闻后果修正
4. 应用卡牌后果修正
5. 应用店铺被动后果修正
6. 应用定价方式后果修正
7. 应用一次性保险 / 临时保险
8. clamp 数值
9. 计算 refund / cashDelta / reputationDelta
```

## 19.4 refundRate 限制

```text
refundRate = clamp(refundRate, 0, 1)
```

## 19.5 fine 限制

```text
fine = max(0, round(fine))
```

## 19.6 reputationLoss 限制

```text
reputationLoss = max(0, round(reputationLoss))
```

## 19.7 退款计算

```text
refund = round(finalPrice × refundRate)
```

## 19.8 现金变化

```text
cashDelta = finalPrice - refund - fine
```

注意：

```text
product.cost 不在出售阶段扣现金。
商品进价已经在进货阶段扣过。
```

## 19.9 信誉变化

```text
reputationDelta = -reputationLoss
```

如果有信誉恢复或事故转化：

```text
reputationDelta += reputationGainModifiers
```

## 19.10 黑红事故转化

如果拥有 passive_black_red_is_red：

条件：

```text
customer == customer_short_video_mcn
finalAccidentLevel == minor
```

效果：

```text
reputationLoss = 0
RunState.resources.heat += 2
```

如果：

```text
customer == customer_short_video_mcn
finalAccidentLevel == major 或 severe
```

效果：

```text
RunState.resources.heat = 0
reputationLoss += 10
```

## 19.11 风险承销

如果本单使用 card_risk_underwriting：

条件：

```text
事故由隐藏标签或暗风险贡献导致
```

效果：

```text
refund 和 fine 对 cash 的影响 ×0.5
reputationLoss 不变
```

实现建议：

```text
cashPenalty = refund + fine
reducedCashPenalty = round(cashPenalty × 0.5)
cashDelta = finalPrice - reducedCashPenalty
```

breakdown 必须显示：

```text
风险承销：现金惩罚减半
```

# 20. 单笔利润与累计利润

## 20.1 单笔利润

```text
singleProfit = finalPrice - product.cost - refund - fine
```

如果风险承销等效果降低现金惩罚，应使用修正后的实际现金惩罚：

```text
singleProfit = finalPrice - product.cost - actualCashPenalty
```

其中：

```text
actualCashPenalty = actualRefundCashLoss + actualFineCashLoss
```

## 20.2 累计利润增加

```text
profitGain = max(0, singleProfit)
```

## 20.3 累计利润奖励

某些规则可以添加：

```text
totalProfitBonus
```

例如：

```text
盲盒价未踩雷：totalProfitBonus +20
黑箱货王无事故出售暗风险商品：totalProfitBonus +15
```

最终：

```text
totalProfitGain = profitGain + totalProfitBonus
```

## 20.4 负利润处理

第一版默认：

```text
如果 singleProfit < 0：
  totalProfit 不减少
  cash 正常承受损失
```

也就是：

```text
RunState.totalProfit += max(0, singleProfit)
```

## 20.5 现金变化

```text
RunState.cash += cashDelta
```

cashDelta 通常为：

```text
finalPrice - refund - fine
```

可能被风险承销、事故转化或特殊卡牌修正。

## 20.6 信誉变化

```text
RunState.reputation += reputationDelta
```

通常：

```text
reputationDelta = -reputationLoss
```

# 21. 出售结算总顺序

玩家点击确认出售后，必须按以下顺序执行：

```text
1. 锁定 product / customer / pricingMode / marketEvent / active modifiers
2. calculatePrice(resolve)
3. calculateRisk(resolve)
4. 得到 finalPrice
5. 得到 finalRisk
6. 根据 finalRisk 得到 baseAccidentLevel
7. applyAccidentLevelModifiers
8. 得到 finalAccidentLevel
9. calculateAccidentOutcome
10. 计算 cashDelta
11. 计算 singleProfit
12. 计算 totalProfitGain
13. 修改 RunState.cash
14. 修改 RunState.totalProfit
15. 修改 RunState.reputation
16. 标记 product.sold = true
17. DayState.soldProductCount += 1
18. 生成 DealResult
19. 如果 finalAccidentLevel != none，生成 AccidentInstance
20. 写入 dealLog / accidentLog / runLog
21. 检查失败条件
22. 刷新 UI
```

# 25. 盲盒价专门规则

## 25.1 可用条件

盲盒价按钮 enabled 条件：

```text
商品存在未揭示 hiddenTag
或
商品存在 darkRisk 且 revealedLevel != full / treated
```

## 25.2 售价效果

```text
priceMultiplier = 1.45
```

## 25.3 风险效果

```text
riskAdd = +20
```

## 25.4 结算时判断

记录出售确认时的未知信息快照：

```text
blindBoxUnknownSnapshot {
  unrevealedHiddenTagIdsAtSell,
  unresolvedDarkRiskAtSell
```

如果出售前未知，出售后才揭示，则参与盲盒判定。

```text
blindBoxResult = "hit_taboo"
```

```text
blindBoxResult = "hit_dark_sensitivity"
```

```text
仍只 accidentLevel +1
```

第一版避免盲盒价惩罚过重。

## 25.6 未命中雷区

如果没有命中：

```text

```

```text
这表示玩家成功把不确定性包装成溢价。
```

# 26. 特殊规则插入点

为了开发清楚，特殊规则统一归入以下插入点。

## 26.1 onBeforePrice

影响 rawPrice 或 multiplier。

示例：

```text
市场新闻标签涨价
顾客预算变化
店铺被动售价加成
卡牌售价加成
```

## 26.2 onBeforeRisk

# 27. 计算伪代码

## 27.1 calculateDealPreview

```text
function calculateDealPreview(context):
  if product == null or customer == null or pricingMode == null:
    return invalid preview

  priceResult = calculatePrice(context with mode = preview)
  riskResult = calculateRisk(context with mode = preview)

  if riskResult.riskDisplayType == "exact":
    accidentPrediction = getAccidentLevel(riskResult.exactRisk)
  else:
    accidentPredictionMin = getAccidentLevel(riskResult.riskMin)
    accidentPredictionMax = getAccidentLevel(riskResult.riskMax)

  estimatedProfit = priceResult.finalPrice - product.cost

  return DealPreview {
    valid: true,
    estimatedPrice: priceResult.finalPrice,
    estimatedProfit,
    riskDisplayType,
    exactRisk,
    riskMin,
    riskMax,
    accidentPrediction,
    accidentPredictionMin,
    accidentPredictionMax,
    priceBreakdown,
    riskBreakdown,
    unknownRiskBreakdown,
    warnings
  }
```

## 27.2 resolveDeal

```text
function resolveDeal(context):
  lock context

  priceResult = calculatePrice(context with mode = resolve)
  riskResult = calculateRisk(context with mode = resolve)

  finalPrice = priceResult.finalPrice
  finalRisk = riskResult.exactRisk

  baseAccidentLevel = getAccidentLevel(finalRisk)

  finalAccidentLevel = applyAccidentLevelModifiers(
    baseAccidentLevel,
    context,
    finalRisk
  )

  accidentOutcome = calculateAccidentOutcome(
    context,
    finalPrice,
    finalRisk,
    finalAccidentLevel
  )

  singleProfit =
    finalPrice
    - product.cost
    - accidentOutcome.actualCashPenalty

  totalProfitGain =
    max(0, singleProfit)
    + accidentOutcome.totalProfitBonus

  cashDelta = accidentOutcome.cashDelta
  reputationDelta = accidentOutcome.reputationDelta

  RunState.cash += cashDelta
  RunState.totalProfit += totalProfitGain
  RunState.reputation += reputationDelta

  product.status = "sold"
  product.flags.sold = true
  product.soldDay = RunState.currentDay
  DayState.soldProductCount += 1

  create DealResult
  if finalAccidentLevel != none:
    create AccidentInstance

  checkFailConditions()

  return DealResult
```
