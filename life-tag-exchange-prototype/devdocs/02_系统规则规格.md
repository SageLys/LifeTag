# 02_系统规则规格

文档编号：02  
文档名称：系统规则规格  
项目名称：《人生标签交易所：牛马肉铺》HTML 快速验证原型  
对应策划案版本：核心策划案 v0.5  
文档版本：v0.1  
用途：定义 HTML 原型中所有核心系统的可执行规则、触发条件、状态修改、禁止条件和验收标准。  
适用对象：游戏设计者、前端开发者、AI Agent / Codex、测试者。

---

# 1. 文档目的

本文档用于把《人生标签交易所：牛马肉铺》的核心玩法转化为程序可执行的系统规则。

本文档不负责：

- 编写具体 UI 布局；
    
- 编写完整配置数据；
    
- 编写最终数值平衡；
    
- 编写剧情文案；
    
- 编写正式版 Unity 架构。
    

本文档负责：

1. 定义每个系统的规则边界；
    
2. 明确每条规则的触发条件；
    
3. 明确每条规则修改哪些状态；
    
4. 明确每条规则禁止什么行为；
    
5. 明确每条规则如何被测试；
    
6. 避免开发时把玩法理解成“普通标签匹配小游戏”。
    

---

# 2. 核心设计约束

## 2.1 原型核心

本 HTML 原型必须保护以下核心：

```text
每日经营
+
标签加工
+
现金构筑
+
隐藏标签 / 暗风险
+
爆雷复盘
+
肉鸽成长
```

## 2.2 绝对规则

以下规则不得被开发实现破坏。

### CORE_001：累计利润是通关目标

累计利润 `totalProfit` 是本局唯一核心通关目标。

```text
胜利检查使用 totalProfit。
现金 cash 不等同于通关进度。
```

### CORE_002：现金是构筑资源

现金 `cash` 是当前可支配资源。

现金可以被用于：

- 进货；
    
- 洗标；
    
- 包装；
    
- 公关；
    
- 使用部分卡牌；
    
- 支付事故退款 / 罚款；
    
- 购买收店奖励；
    
- 升级卡牌；
    
- 删除卡牌；
    
- 获得店铺被动；
    
- 获得货源倾向；
    
- 处理暗风险。
    

### CORE_003：信誉是生命值

信誉 `reputation` 表示店铺是否还能继续经营。

```text
reputation <= 0 时，本局失败。
```

### CORE_004：爆雷不是全局资源

爆雷值 `risk` 是每笔交易的临时计算结果，不是 RunState 的长期资源。

```text
每次交易重新计算 risk。
交易结束后不保留为全局数值。
```

### CORE_005：事故不使用随机判定

事故是否发生只由最终爆雷值决定。

```text
允许随机生成商品、隐藏标签、暗风险、顾客、市场新闻、抽牌、奖励。
禁止随机决定事故是否发生。
```

### CORE_006：普通鉴定不能完全揭示暗风险

基础操作【鉴定】只能揭示隐藏真实标签。

```text
普通鉴定不得揭示暗风险具体内容。
暗风险只能通过经营手法牌、店铺被动或高级规则部分处理。
```

### CORE_007：赌博机制不做独立系统

“赌一把”不新增独立盲盒系统。

赌博感必须压回：

- 盲盒价；
    
- 经营手法牌；
    
- 店铺被动；
    
- 货源倾向；
    
- 暗风险；
    
- 未揭示隐藏标签。
    

### CORE_008：事故必须可复盘

每次事故必须输出事故链条。

事故链条至少包括：

- 最终爆雷值；
    
- 事故等级；
    
- 主要风险来源；
    
- 主要未知风险来源；
    
- 触发事故的标签；
    
- 触发事故的顾客雷区；
    
- 触发事故的定价方式；
    
- 触发事故的卡牌或被动。

# 3. 规则书写标准

本文档中的规则采用以下格式：

```text
规则编号：
规则名称：
触发条件：
前置条件：
执行内容：
修改数据：
禁止事项：
UI 反馈：
测试标准：
```

示例：

```text
RULE_CASH_001：
现金低于 0 时失败。

触发条件：
任意 action 或结算导致 RunState.cash 发生变化。

前置条件：
RunState.cash < 0。

执行内容：
RunState.result = "failed"。
RunState.failReason = "cash_below_zero"。
RunState.phase = "RUN_FAILED"。

修改数据：
RunState.result
RunState.failReason
RunState.phase

UI 反馈：
显示失败报告。

测试标准：
事故退款导致现金从 10 变为 -20 时，立即进入失败。
```

# 4. 单局规则

## RUN_001：新局初始化

### 触发条件

玩家点击：

```text
开始新局
```

### 执行内容

初始化 RunState：

```text
currentDay = 1
cash = GameConfig.initialCash
totalProfit = 0
reputation = GameConfig.initialReputation
inventory = []
activePassives = []
activeSupplySources = []
runLog = []
dealLog = []
accidentLog = []
result = "running"
```

初始化 DeckState：

```text
drawPile = initialDeck
hand = []
discardPile = []
exhaustPile = []
```

### 修改数据

- RunState；
    
- DeckState；
    
- DayState。
    

### 测试标准

开始新局后，顶部栏必须显示：

```text
第 1 / 8 天
现金 100
累计利润 0 / 500
信誉 100
库存 0 / 6
```

---

## RUN_002：每日开始

### 触发条件

满足任一条件：

1. 新局初始化完成；
    
2. 前一天收店奖励选择完成；
    
3. 当前天数小于等于最大天数。
    

### 执行内容

创建或重置 DayState：

```text
dayNumber = RunState.currentDay
phase = DAY_OPENING
actionPoints = GameConfig.dailyActionPoints
boughtProductCount = 0
soldProductCount = 0
selectedProductId = null
selectedCustomerId = null
selectedPricingModeId = null
currentDealPreview = null
rewardOptions = []
```

处理库存新鲜度：

```text
所有未售商品 freshnessCurrent -= 1
如果 freshnessCurrent <= 0，则标记 spoiled = true
```

### 禁止事项

不得在每日开始时清空库存。  
不得在每日开始时清空已获得店铺被动。  
不得在每日开始时清空累计利润。

### 测试标准

第 2 天开始时：

- 当前天数变为 2；
    
- 行动点恢复到 3；
    
- 库存中未售商品仍存在；
    
- 未售商品新鲜度减少。
    

---

## RUN_003：胜利判定

### 触发条件

第 8 天收店阶段结束后。

### 前置条件

```text
RunState.currentDay == GameConfig.runLengthDays
```

### 胜利条件

必须同时满足：

```text
RunState.totalProfit >= GameConfig.targetTotalProfit
RunState.cash >= 0
RunState.reputation > 0
```

### 执行内容

```text
RunState.result = "victory"
RunState.phase = "RUN_END"
生成 RunReport
```

### 测试标准

第 8 天结束时：

```text
totalProfit = 520
cash = 80
reputation = 35
```

结果必须为胜利。

---

## RUN_004：失败判定

### 触发条件

任意状态变化后检查。

### 失败条件

满足任一条件：

```text
RunState.cash < 0
RunState.reputation <= 0
```

或者第 8 天结束时：

```text
RunState.totalProfit < GameConfig.targetTotalProfit
```

### 失败类型

```text
cash_below_zero
reputation_zero
profit_target_not_met
```

### 执行内容

```text
RunState.result = "failed"
RunState.failReason = 对应失败原因
RunState.phase = "RUN_FAILED"
生成 RunReport
```

### 测试标准

事故结算后信誉从 20 降到 0，必须立即失败。

---

# 5. 核心资源规则

## RES_CASH_001：现金扣除

### 触发条件

以下行为发生时：

- 进货；
    
- 洗标；
    
- 包装；
    
- 公关；
    
- 使用现金成本卡牌；
    
- 选择付费奖励；
    
- 支付事故退款；
    
- 支付事故罚款。
    

### 执行内容

```text
RunState.cash -= cost
```

### 禁止事项

除事故结算外，玩家主动操作不得让现金变为负数。

主动操作包括：

- 进货；
    
- 洗标；
    
- 包装；
    
- 公关；
    
- 出牌；
    
- 选择奖励。
    

如果现金不足，按钮 disabled。

### 测试标准

现金为 10 时，【洗标】成本 20，洗标按钮必须不可点击。

---

## RES_CASH_002：现金增加

### 触发条件

以下行为发生时：

- 出售商品获得成交收入；
    
- 卡牌效果获得现金；
    
- 奖励获得现金；
    
- 被动效果获得现金；
    
- 特殊事故转化收益。
    

### 执行内容

```text
RunState.cash += amount
```

### 测试标准

出售收入 150，事故退款 0 时，当前现金 80，应变为 230。

---

## RES_PROFIT_001：累计利润增加

### 触发条件

出售结算完成后。

### 单笔利润计算

```text
singleProfit =
finalPrice
- product.cost
- accidentRefund
- accidentFine
```

### 累计利润变化

```text
RunState.totalProfit += max(0, singleProfit)
```

### 禁止事项

以下支出不得扣累计利润：

- 进货外的现金支出；
    
- 洗标成本；
    
- 包装成本；
    
- 公关成本；
    
- 卡牌使用成本；
    
- 卡牌升级成本；
    
- 删除卡牌成本；
    
- 购买店铺被动成本；
    
- 购买货源倾向成本。
    

注意：商品进价参与单笔利润计算，但在现金上已经于进货阶段扣除，不得在出售时重复扣现金。

### 测试标准

商品进价 40，最终成交收入 160，无事故：

```text
singleProfit = 160 - 40 = 120
totalProfit += 120
cash += 160
```

---

## RES_REPUTATION_001：信誉减少

### 触发条件

事故结算、特殊事件或卡牌副作用导致信誉损失。

### 执行内容

```text
RunState.reputation -= reputationLoss
```

### 下限检查

如果：

```text
RunState.reputation <= 0
```

立即失败。

### 测试标准

信誉 20，严重事故信誉损失 35，结算后进入失败。

---

## RES_REPUTATION_002：信誉恢复

### 触发条件

以下行为可能恢复信誉：

- 公关选择“店铺信誉 +10”；
    
- 收店奖励；
    
- 特殊卡牌；
    
- 店铺被动。
    

### 执行内容

```text
RunState.reputation = min(GameConfig.maxReputation, RunState.reputation + value)
```

### 测试标准

信誉 95，公关恢复 10，最终信誉应为 100，不得超过上限。

---

## RES_AP_001：行动点消耗

### 触发条件

以下行为默认消耗行动点：

- 鉴定；
    
- 洗标；
    
- 包装；
    
- 公关；
    
- 大部分标签工具牌；
    
- 大部分经营手法牌；
    
- 深度背调；
    
- 高级暗风险处理。
    

### 执行内容

```text
DayState.actionPoints -= actionPointCost
```

### 禁止事项

如果行动点不足，操作按钮 disabled。

### 测试标准

行动点为 0 时，鉴定、洗标、包装、公关全部不可用。

---

# 6. 商品系统规则

## PROD_001：商品候选生成

### 触发条件

进入进货阶段时。

### 执行内容

生成 `GameConfig.dailyProductCandidateCount` 个 ProductInstance，状态为：

```text
status = "candidate"
```

默认数量：

```text
4
```

### 生成依据

商品生成应考虑：

- ProductTemplate.spawnWeight；
    
- 当前市场新闻；
    
- 当前货源倾向；
    
- 当前天数；
    
- 商品模板暗风险概率；
    
- 商品隐藏标签池。
    

### 修改数据

```text
DayState.productCandidates
```

### 测试标准

进入进货阶段后，商品候选区必须出现 4 个候选商品。

---

## PROD_002：商品买入

### 触发条件

玩家点击候选商品的“买入”。

### 前置条件

必须同时满足：

```text
RunState.cash >= product.cost
DayState.boughtProductCount < GameConfig.dailyProductBuyLimit
RunState.inventory.length < GameConfig.inventoryLimit
product.status == "candidate"
```

### 执行内容

```text
RunState.cash -= product.cost
product.status = "inventory"
RunState.inventory.push(product)
DayState.boughtProductCount += 1
```

### 禁止事项

不得买入已买入商品。  
不得超出每日进货上限。  
不得超出库存上限。  
不得主动买到现金为负。

### 测试标准

现金 100，买入进价 40 的商品后：

```text
cash = 60
inventory.length += 1
boughtProductCount += 1
```

---

## PROD_003：商品库存保留

### 触发条件

每日结束或进入下一天。

### 执行内容

未售商品保留在库存中。  
已售商品不可再次出售。  
腐败商品仍可保留，但根据新鲜度规则降低价值或增加风险。

### 禁止事项

不得在每日结束时自动清空所有库存。

### 测试标准

第 1 天买入但未售出的商品，第 2 天仍应出现在库存中。

---

## PROD_004：商品售出

### 触发条件

出售结算完成。

### 执行内容

```text
product.flags.sold = true
product.status = "sold"
DayState.soldProductCount += 1
```

### 禁止事项

已售商品不得再次选择出售。  
已售商品不得继续被鉴定、洗标、包装、公关或出牌作用。

### 测试标准

商品售出后，出售按钮对该商品不可用。

---

## PROD_005：商品新鲜度

### 触发条件

每日开始时。

### 执行内容

```text
freshnessCurrent -= GameConfig.freshnessLossPerDay
```

如果：

```text
freshnessCurrent <= 0
```

则：

```text
product.flags.spoiled = true
```

### 腐败效果

第一版推荐：

```text
spoiled 商品 finalPrice -20
spoiled 商品 finalRisk +20
```

具体数值可放入 GameConfig。

### 测试标准

新鲜度 1 的商品进入下一天后变为 0，并显示“已变质”。

---

# 7. 标签系统规则

## TAG_001：标签来源

商品上的标签来源分为：

```text
true_visible
true_hidden
applied
temporary
suppressed
```

含义：

|来源|含义|
|---|---|
|true_visible|显性真实标签，初始可见|
|true_hidden|隐藏真实标签，鉴定后可见|
|applied|玩家通过卡牌或操作添加的包装标签|
|temporary|临时效果，不一定显示为正式标签|
|suppressed|被洗标或卡牌压制的标签|

---

## TAG_002：显性真实标签

### 规则

显性真实标签初始可见。

### 用途

显性真实标签参与：

- 售价计算；
    
- 爆雷计算；
    
- 顾客偏好匹配；
    
- 顾客雷区匹配；
    
- 标签冲突计算；
    
- 事故链条输出。
    

### 测试标准

商品初始拥有 `[年轻] [名校]`，商品卡必须直接显示这两个标签。

---

## TAG_003：隐藏真实标签

### 规则

隐藏真实标签初始不可见，但真实存在。

### 显示

未揭示时显示为：

```text
[?]
```

或：

```text
[? 履历风险]
```

### 参与计算

隐藏标签在预览阶段分两种：

1. 未揭示时参与风险区间；
    
2. 揭示后参与精确价格 / 风险计算。
    

### 出售结算

出售结算必须使用真实隐藏标签计算最终结果。

### 测试标准

隐藏标签 `[水货]` 未揭示时，预览显示爆雷区间；鉴定后应显示 `[水货]` 并更新风险。

---

## TAG_004：包装标签

### 规则

包装标签由标签工具牌或特定操作添加。

### 用途

包装标签通常：

- 提高售价；
    
- 提高爆雷；
    
- 与真实标签产生支撑或冲突；
    
- 影响事故文案。
    

### 禁止事项

包装标签不等同于真实标签。  
包装标签不得替代真实标签。  
如果包装标签与真实标签冲突，应增加虚假包装风险。

### 测试标准

给 `[水货] [名校]` 商品添加 `[名校背书]` 后，爆雷应明显上升。

---

## TAG_005：被压制标签

### 规则

洗标或经营手法牌可以将标签加入 `suppressedTags`。

### 效果

被压制标签：

- 仍保留在商品数据中；
    
- UI 可显示为“已压制”；
    
- 在价格 / 风险计算中按规则降低影响；
    
- 在事故链条中可作为“被处理过的风险”显示。
    

### 禁止事项

洗标不得物理删除真实标签。  
洗标不得直接处理暗风险，除非卡牌或被动明确允许。

### 测试标准

商品 `[水货]` 被洗标后，商品仍可查看历史上存在 `[水货]`，但交易风险降低。

---

# 8. 暗风险系统规则

## DARK_001：暗风险存在规则

### 规则

部分商品可以存在暗风险。

暗风险数据包含：

```text
exists
category
revealedLevel
darkTagId
riskRange
actualRiskValue
```

### 暗风险类别

第一版只允许：

```text
career_background
persona
platform
```

对应显示：

```text
履历风险
人设风险
平台风险
```

---

## DARK_002：暗风险初始显示

### 规则

暗风险不是完全无提示。

初始显示至少应提供：

```text
无
存在
类别可能
```

示例：

```text
暗风险：存在
暗风险：履历类可能
```

### 禁止事项

不得出现完全无提示的随机炸弹。

---

## DARK_003：普通鉴定不能完全揭示暗风险

### 触发条件

玩家使用基础操作【鉴定】。

### 执行内容

鉴定只揭示隐藏真实标签。

普通鉴定最多可以把暗风险从：

```text
unknown
```

变成：

```text
existence_only
```

或保持原状态。

### 禁止事项

不得通过普通鉴定揭示：

```text
darkTagId
actualRiskValue
full accident consequence
```

---

## DARK_004：深度背调揭示暗风险类别

### 触发条件

玩家使用【深度背调】或类似经营手法牌。

### 前置条件

```text
selectedProduct.darkRisk.exists == true
RunState.cash >= cost
DayState.actionPoints >= actionPointCost
```

### 执行内容

```text
selectedProduct.darkRisk.revealedLevel = "category"
```

可选附加：

```text
如果暗风险类别与卡牌适配，本单 risk -10
```

### 测试标准

使用深度背调后，交易预览风险区间应缩小，但不一定完全变成精确值。

---

## DARK_005：暗风险完全处理

### 触发条件

高级卡牌、店铺被动或特殊奖励明确允许。

### 执行内容

```text
selectedProduct.darkRisk.revealedLevel = "full"
```

或：

```text
添加 darkRiskReduction modifier
```

### 测试标准

暗风险完全处理后，交易预览可以显示精确爆雷值。

# 18. 售价计算规则

## CALC_PRICE_001：售价计算时机

以下情况必须重新计算售价预览：

- 选中商品变化；
    
- 选中顾客变化；
    
- 选中定价方式变化；
    
- 商品标签变化；
    
- 隐藏标签揭示；
    
- 包装状态变化；
    
- 被压制标签变化；
    
- 卡牌效果变化；
    
- 市场新闻变化；
    
- 店铺被动变化。
    

---

## CALC_PRICE_002：售价组成

第一版售价计算公式：

```text
rawPrice =
product.basePrice
+ knownTrueTagPrice
+ appliedTagPrice
+ customerPreferencePrice
+ marketEventPriceModifier
+ cardPriceModifier
+ passivePriceModifier
+ freshnessPriceModifier
```

然后计算倍率：

```text
finalPrice =
rawPrice
× packageMultiplier
× pricingModeMultiplier
× passiveMultiplier
```

最后：

```text
finalPrice = max(1, round(finalPrice))
finalPrice = min(finalPrice, customer.budget)
```

如果特殊规则允许突破预算，则跳过预算上限。

---

## CALC_PRICE_003：价格拆解

售价预览必须输出：

```text
priceBreakdown = [
  { sourceType, sourceId, label, value, operation }
]
```

示例：

```text
基础价：50
[名校]：+20
大厂 HR 偏好 [名校]：+25
今日新闻：+20
高价卖：×1.3
```

# 20. 事故系统规则

## ACCIDENT_001：事故等级判定

根据 finalRisk 判定：

```text
0–39：none
40–59：minor
60–79：medium
80–99：major
100+：severe
```

---

## ACCIDENT_002：事故修正顺序

事故等级修正顺序：

```text
1. 根据 finalRisk 得到基础事故等级
2. 应用顾客特殊规则
3. 应用市场新闻特殊规则
4. 应用卡牌特殊规则
5. 应用店铺被动特殊规则
6. 应用盲盒价特殊规则
7. 限制事故等级在 none ~ severe 之间
```

---

## ACCIDENT_003：事故后果

事故至少产生：

```text
refund
fine
reputationLoss
accidentTitle
accidentText
accidentChain
```

推荐默认值：

|事故等级|退款|罚款|信誉损失|
|---|--:|--:|--:|
|none|0%|0|0|
|minor|10%|0|5|
|medium|30%|0|15|
|major|50%|10|30|
|severe|80%|30|45|

具体数值放入 AccidentDef 或 GameConfig。

---

## ACCIDENT_004：事故结算现金

```text
RunState.cash += finalPrice
RunState.cash -= refund
RunState.cash -= fine
```

注意：

商品进价已在进货时扣除，不在事故结算时再次扣现金。

---

## ACCIDENT_005：事故结算信誉

```text
RunState.reputation -= reputationLoss
```

如果被动或卡牌修改事故结果，应在扣信誉前处理。

---

## ACCIDENT_006：事故链条

事故链条必须显示：

```text
最终爆雷值
事故等级
风险来源列表
顾客雷区来源
市场新闻来源
定价来源
卡牌来源
暗风险来源
修正来源
最终现金与信誉后果
```

## REWARD_002：奖励选择

```text

```

# 26. 系统规则验收清单

完成实现后，必须逐项检查：

## 26.1 资源规则

- 现金可以增减；
    
- 现金小于 0 失败；
    
- 累计利润只由交易利润增加；
    
- 支出不扣累计利润；
    
- 信誉小于等于 0 失败；
    
- 行动点每日刷新；
    
- 行动点不足时操作不可用。
    

## 26.2 商品规则

- 商品可生成；
    
- 商品可买入；
    
- 商品可进入库存；
    
- 商品可出售；
    
- 商品售出后不可再次出售；
    
- 商品隐藏标签可鉴定；
    
- 暗风险不会被普通鉴定完全揭示。
    

## 26.3 交易规则

- 交易预览可生成；
    
- 未知信息存在时显示风险区间；
    
- 信息完全时显示精确风险；
    
- 出售后现金更新；
    
- 出售后累计利润更新；
    
- 出售后事故正确触发；
    
- 事故链条可见。
    

## 26.4 构筑规则

- 每日抽牌；
    
- 卡牌可使用；
    
- 卡牌进入弃牌堆；
    
- 每日收店奖励可选；
    
- 店铺被动可持续生效；
    
- 货源倾向可影响商品生成。
    

## 26.5 结局规则

- 第 8 天可胜利；
    
- 第 8 天利润不足失败；
    
- 现金负数失败；
    
- 信誉归零失败；
    
- 最终报告显示核心数据。

# 27. 本文档结论

本系统规则规格的核心是把 v0.5 的玩法约束转成可执行规则。

开发时必须始终保持：

```text
现金不是胜利目标，而是构筑燃料。
累计利润才是胜利目标。
信誉是血量。
行动点制造每日取舍。
隐藏标签制造基础不确定性。
暗风险制造高级赌博张力。
事故由爆雷阈值确定。
事故必须可解释、可复盘。
奖励必须推动店铺形成流派。
```

如果某个实现方案破坏这些规则，应视为不符合第一版 HTML 原型目标。
