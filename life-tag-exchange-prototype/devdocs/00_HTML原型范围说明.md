# 1. 文档目的

本文档用于回答第一版 HTML 原型到底要做什么、不做什么、做到什么程度才算完成。

本原型不是正式版游戏，不追求完整美术、完整内容量、长期运营结构或复杂商业化系统。  
本原型的核心目的只有一个：

验证《人生标签交易所：牛马肉铺》的核心玩法闭环是否成立。

具体需要验证：

1. 玩家是否能理解每日经营流程；
    
2. 玩家是否能理解现金、累计利润、信誉、行动点、爆雷之间的关系；
    
3. 玩家是否能通过标签、顾客、市场新闻做出策略判断；
    
4. 玩家是否能感受到“买入问题货 → 加工包装 → 高价出售 → 压爆雷套利”的核心爽点；
    
5. 隐藏标签和暗风险是否能制造有效的“赌一把”张力；
    
6. 每日收店奖励是否能形成构筑成长感；
    
7. 事故结算和事故链条是否能让玩家清楚复盘；
    
8. 该系统是否值得继续扩展到 Unity 正式版。

# 2. 原型定位

## 2.1 类型定位

本 HTML 原型是：

- 单页文字经营策略小游戏；
    
- 肉鸽构筑原型；
    
- 标签加工与交易原型；
    
- 信息不完全风险套利原型；
    
- 可快速迭代的规则验证工具。
    

本 HTML 原型不是：

- 正式商业版本；
    
- Unity 最终版本；
    
- 完整模拟经营游戏；
    
- 复杂卡牌战斗游戏；
    
- 大量剧情驱动游戏；
    
- 美术展示 Demo；
    
- 完整数值平衡版本。
    

## 2.2 核心体验定位

玩家在一局 8 天内经营一家荒诞“牛马肉铺”。

每日核心体验为：

```text
看今日市场新闻
→ 选择买入牛马肉
→ 阅读顾客需求和雷区
→ 判断商品隐藏标签和暗风险
→ 用行动点、现金、基础操作和手牌加工商品
→ 选择顾客与定价方式
→ 查看售价与爆雷预览
→ 决定稳卖或赌一把
→ 结算收入、累计利润、事故和信誉
→ 收店时用现金购买成长
→ 店铺逐渐形成流派
```

第一版必须让玩家感到：

```text
我不是在做单纯标签匹配。
我是在利用有限信息、市场风向、加工手段和现金资源，把有问题的商品加工成高利润商品。
我知道这单有风险，但我可以判断是否值得赌。
如果炸了，我也能知道是哪个标签、哪个包装、哪个暗风险和哪个贪婪选择导致了事故。
```

# 3. 原型平台与技术边界

## 3.1 目标平台

第一版目标平台：

```text
桌面浏览器
```

优先适配：

- Chrome；
    
- Edge；
    
- 本地文件运行；
    
- 简单静态网页部署。
    

暂不优先适配：

- 手机竖屏；
    
- 平板触屏；
    
- 手柄；
    
- 微信小游戏；
    
- Steam；
    
- Unity WebGL。
    

## 3.2 技术形式

推荐第一版采用：

```text
HTML + CSS + JavaScript
```

可选增强方案：

```text
Vite + TypeScript
```

但第一版开发应以“最快形成可玩闭环”为准，不应因工程复杂度拖慢验证。

## 3.3 数据形式

第一版推荐使用 JSON 配置。

推荐目录：

```text
/data/gameConfig.json
/data/tags.json
/data/darkRisks.json
/data/products.json
/data/customers.json
/data/marketEvents.json
/data/cards.json
/data/passives.json
/data/supplySources.json
/data/pricingModes.json
/data/accidents.json
/data/rewards.json
```

要求：

1. 游戏对象尽量数据驱动；
    
2. 标签、商品、顾客、市场新闻、卡牌、被动、定价方式、事故尽量不硬编码；
    
3. 计算逻辑可以写在 JS 规则模块中；
    
4. 中文只作为显示文本；
    
5. 内部逻辑使用英文 ID。

# 4. 第一版原型的核心目标

## 4.1 必须验证的核心问题

第一版 HTML 原型必须验证以下问题：

### 问题 1：每日经营循环是否清楚

玩家是否能理解每天依次做什么：

```text
看新闻
买货
看顾客
抽牌
加工
出售
结算
选奖励
```

### 问题 2：现金作为构筑资源是否成立

现金不是通关进度本身，而是局内可支配资源。

玩家需要用现金：

- 进货；
    
- 洗标；
    
- 包装；
    
- 公关；
    
- 使用部分卡牌；
    
- 支付事故成本；
    
- 购买收店奖励；
    
- 升级卡牌；
    
- 删除卡牌；
    
- 获得店铺被动；
    
- 获得货源倾向。
    

验证目标：

```text
玩家是否愿意把当前赚到的钱投入成长，而不是只囤钱。
```

### 问题 3：累计利润作为通关目标是否直观

累计利润是通关目标。

验证目标：

```text
玩家是否能清楚知道自己距离胜利还差多少经营成果。
```

### 问题 4：隐藏标签是否制造基础不确定性

商品应有：

- 显性真实标签；
    
- 可鉴定隐藏标签；
    
- 暗风险提示。
    

验证目标：

```text
玩家是否会在“花行动点鉴定”和“直接赌高价”之间取舍。
```

### 问题 5：暗风险是否制造高级赌博张力

暗风险不能被普通鉴定完全消除。

验证目标：

```text
玩家是否能接受“系统给了线索，但没有完全公开答案”的风险交易。
```

### 问题 6：确定性爆雷是否能复盘

事故不是随机骰子触发，而是由最终爆雷值达到阈值后确定触发。

验证目标：

```text
玩家炸店后是否能理解自己为什么炸。
```

### 问题 7：收店奖励是否能产生构筑感

每日结束三选一奖励必须让玩家逐渐形成路线。

验证目标：

```text
玩家是否能感觉店铺从普通肉铺变成特定黑心机器。
```

# 5. 单局范围

## 5.1 单局基础参数

第一版 HTML 原型采用以下默认参数：

|参数|默认值|
|---|--:|
|单局天数|8 天|
|目标累计利润|500|
|初始现金|100|
|初始信誉|100|
|最大信誉|100|
|每日行动点|3|
|每日商品候选|4|
|每日可进货数量|2|
|每日顾客订单|3|
|每日抽牌数量|5|
|初始牌组数量|10|
|库存上限|6|
|每日最低出售|1 单|
|每日市场新闻|1 条|
|每日收店奖励|3 选 1|
|中期事件|第 4 天，可先做成普通新闻强化|
|最终清算|第 8 天结算后|

## 5.2 胜利条件

第 8 天结束时，满足全部条件则胜利：

```text
累计利润 >= 500
现金 >= 0
信誉 > 0
```

## 5.3 失败条件

任意时刻满足以下任一条件，则失败：

```text
现金 < 0
信誉 <= 0
```

## 5.4 失败触发时机

失败可以在以下时机触发：

1. 进货或付费操作后现金低于 0；
    
2. 出售事故结算后现金低于 0；
    
3. 出售事故结算后信誉小于等于 0；
    
4. 收店奖励扣费后现金低于 0；
    
5. 任何规则修改导致资源越界。
    

第一版中，按钮层面应尽量避免玩家主动支付到现金为负。  
但事故退款、罚款等结算可以导致现金为负。

# 6. 第一版必须实现范围

## 6.1 P0：必须实现

以下内容为第一版 HTML 原型必须实现项。

### 单局结构

- 8 天单局；
    
- 第 1 天开局；
    
- 每日流程推进；
    
- 第 8 天结束结算；
    
- 胜利失败判定；
    
- 最终经营报告。
    

### 核心资源

- 现金；
    
- 累计利润；
    
- 信誉；
    
- 行动点；
    
- 库存容量；
    
- 当前天数。
    

### 商品系统

- 商品候选生成；
    
- 商品买入；
    
- 商品进入库存；
    
- 商品出售；
    
- 商品售出后不可再次出售；
    
- 商品新鲜度字段；
    
- 显性真实标签；
    
- 隐藏真实标签；
    
- 暗风险字段；
    
- 包装标签；
    
- 被压制标签；
    
- 商品状态标记。
    

### 标签系统

- 标签定义；
    
- 标签价格价值；
    
- 标签风险价值；
    
- 标签是否负面；
    
- 标签是否可洗；
    
- 标签类别；
    
- 标签显示。
    

### 信息系统

- 未鉴定隐藏标签显示为问号或风险提示；
    
- 鉴定可揭示隐藏标签；
    
- 普通鉴定不能完全揭示暗风险；
    
- 交易预览根据未知信息显示精确爆雷或爆雷区间。
    

### 顾客系统

- 每日生成 3 个顾客订单；
    
- 顾客有偏好标签；
    
- 顾客有雷区标签；
    
- 顾客有预算；
    
- 顾客有风险容忍；
    
- 顾客有暗风险敏感类型。
    

### 市场新闻系统

- 每日生成 1 条市场新闻；
    
- 市场新闻影响标签价格、风险、顾客预算或事故结果；
    
- 市场新闻在 UI 中显示；
    
- 市场新闻影响当日交易计算。
    

### 牌组系统

- 初始牌组；
    
- 每日抽 5 张牌；
    
- 手牌显示；
    
- 可打出标签工具牌；
    
- 可打出经营手法牌；
    
- 打出后进入弃牌堆或当日已使用状态；
    
- 抽牌堆耗尽后可以洗弃牌堆。
    

### 基础操作

必须实现 4 个基础操作：

1. 鉴定；
    
2. 洗标；
    
3. 包装；
    
4. 公关。
    

### 定价系统

必须实现 4 种定价方式：

1. 便宜卖；
    
2. 正常卖；
    
3. 高价卖；
    
4. 盲盒价。
    

### 出售系统

必须实现：

- 选择商品；
    
- 选择顾客；
    
- 选择定价方式；
    
- 生成交易预览；
    
- 确认出售；
    
- 结算成交收入；
    
- 结算现金；
    
- 结算累计利润；
    
- 结算信誉；
    
- 结算事故；
    
- 生成交易日志。
    

### 售价与爆雷预览

必须显示：

- 预计售价；
    
- 预计利润；
    
- 精确爆雷值或爆雷区间；
    
- 预计事故等级或事故等级区间；
    
- 主要加价来源；
    
- 主要风险来源；
    
- 未知风险提示；
    
- 当前定价方式。
    

### 事故系统

必须实现：

- 确定性风险阈值；
    
- 无事故；
    
- 小事故；
    
- 中事故；
    
- 大事故；
    
- 严重事故；
    
- 事故退款；
    
- 信誉损失；
    
- 事故文案；
    
- 事故链条展示。
    

### 收店奖励系统

必须实现：

- 每日结束出现 3 个奖励；
    
- 玩家选择 1 个；
    
- 奖励可以免费；
    
- 奖励可以消耗现金；
    
- 现金不足时奖励不可选；
    
- 奖励类型至少包括：获得卡牌、获得店铺被动、获得货源倾向。
    

### 最终报告

必须实现：

- 胜利或失败结果；
    
- 最终累计利润；
    
- 最终现金；
    
- 最终信誉；
    
- 总事故次数；
    
- 最大单笔利润；
    
- 最大事故；
    
- 主要流派倾向；
    
- 主要爆雷原因；
    
- 文案评价。

# 7. 第一版建议实现范围

## 7.1 P1：强烈建议实现

以下内容不是最低可玩闭环的绝对必要条件，但强烈建议第一版实现，否则构筑感会偏弱。

### 店铺被动

- 获得后持续生效；
    
- 不进入牌组；
    
- 影响价格、风险、事故或奖励；
    
- 至少实现 3 个代表流派的被动。
    

最低实现：

```text
黑红也是红
洗标流水线
大厂背书合作
```

### 货源倾向

- 作为收店奖励出现；
    
- 持续未来若干天；
    
- 改变商品模板生成权重；
    
- 至少实现 3 个流派倾向。
    

最低实现：

```text
校招剩料
流量冻肉
婚恋精品库
```

### 卡牌升级

第一版可以简化为：

```text
升级后数值更高
```

例如：

```text
热搜预热：售价 +35 → +50
```

### 删除卡牌

第一版可以简化为：

```text
从牌组中删除一张指定卡牌
```

### 标签冲突

第一版至少实现核心冲突：

```text
水货 + 名校背书
会发疯 + 家长委员会
低薪接受 + 维权意识强
空心人设 + 体面包装
```

### 三个核心流派

第一版至少要能看出：

1. 大厂牛马流；
    
2. 稳定相亲流；
    
3. MCN 发疯流。
    

不要求完全平衡，但要有可识别的收益与风险模式。

10. 可以选择商品、顾客、定价方式；

## 14.2 体验验收

必须满足：

1. 玩家知道每天该做什么；
    
2. 玩家知道现金和累计利润不是同一个东西；
    
3. 玩家知道信誉是血量；
    
4. 玩家知道行动点限制每日加工；
    
5. 玩家知道隐藏标签可以鉴定；
    
6. 玩家知道暗风险不能被普通鉴定完全消除；
    
7. 玩家知道盲盒价为什么是赌；
    
8. 玩家知道事故不是随机坑自己；
    
9. 玩家能从事故链条复盘；
    
10. 玩家能感受到至少一种构筑路线。

必须满足：

1. 游戏可在浏览器运行；

# 19. 本文档结论

第一版 HTML 原型的开发目标是：

```text
用最小美术成本和中等内容规模，验证“每日经营 + 标签加工 + 现金构筑 + 隐藏标签 / 暗风险 + 爆雷复盘 + 肉鸽成长”是否成立。
```

开发时必须优先保护以下核心：

```text
现金是构筑资源。
累计利润是通关目标。
信誉是血量。
行动点制造取舍。
隐藏标签提供基础不确定性。
暗风险提供高级赌博张力。
事故由爆雷阈值确定。
事故必须可复盘。
收店奖励必须形成构筑成长。
```

只要这组核心成立，后续才有必要扩充内容、强化美术、迁移 Unity、制作正式版。
