# 1. 文档目的

本文档定义 HTML 原型的玩家可见 UI。v0.2 起，UI 不再采用“阶段页 + 下一步按钮”结构，而采用：

```text
仿真店铺主界面
+
可点击店铺区域 ShopZone
+
当前区域详情 ContextPanel
+
常驻交易预览 DealPreviewDock
+
手牌底栏 HandDock
+
日志抽屉 LogDrawer
```

本文档不改变玩法公式、结算、数值和配置。

---

# 2. UI 设计总原则

## 2.1 店铺空间优先

玩家看到的主界面必须像一间可经营的牛马肉铺，而不是网页流程表。

旧 UI：

```text
阶段条 + 当前阶段页面 + 下一阶段按钮
```

新 UI：

```text
一间店铺。
公告牌、后门货源、订单板、牌盒、冷柜、砧板、收银台、账本、保险柜都是可点击区域。
```

## 2.2 单页应用原则

仍然是单页应用。不要做多页面路由跳转。

## 2.3 不泄露隐藏信息原则

未揭示隐藏标签不得显示真实标签名。暗风险未完全揭示时，不得显示具体 darkRiskId、实际风险值或完整事故文案。

## 2.4 disabled 可解释原则

所有不可点击按钮必须显示原因。

示例：

```text
现金不足，需要 20 现金。
行动点不足。
没有库存商品。
请先选择顾客。
今日已经日结。
该商品没有未知信息，不能使用盲盒价。
```

## 2.5 交易预览常驻原则

只要玩家进入加工、出售、库存、订单、定价相关区域，交易预览都应可见或固定在右侧 / 下方 Dock。

# 5. ShopZone 规格

每个 ShopZone 必须显示：

```text
区域名
功能说明
状态标记
可点击状态
disabledReason，若不可点击
```

建议区域：

| 区域 | 显示名 | 功能 |
|---|---|---|
| news | 公告牌 | 今日市场新闻 |
| supply | 后门货源 | 进货 |
| orders | 订单板 | 顾客订单 |
| deck | 牌盒 | 抽牌 / 牌库 |
| inventory | 冷柜 | 库存 |
| process | 砧板 | 鉴定、洗标、包装、公关、出牌 |
| cashier | 收银台 | 出售 |
| daybook | 账本 | 日结 |
| reward | 保险柜 | 收店奖励 |
| passives | 店铺状态 | 被动与货源倾向 |

# 6. TodayTaskBar

TodayTaskBar 代替旧 PhaseGuideBar。

显示：

```text
新闻：未查看 / 已查看
进货：0/2、1/2、2/2
订单：未接单 / 已接单
抽牌：未抽牌 / 手牌 5
出售：0/1 或今日成交数
日结：未完成 / 已日结
收店：未开放 / 待选择 / 已完成
```

TodayTaskBar 只是状态提示，不应强制线性推进。

---

# 7. ContextPanel

ContextPanel 显示当前点击区域的详情。

## 7.1 news

显示今日新闻、效果摘要、受影响标签 / 顾客 / 暗风险类别。

## 7.2 supply

显示今日商品候选、买入按钮、进货上限、库存上限、现金状态。

## 7.3 orders

显示顾客订单，可选择顾客。顾客选择不再限定为处理 / 出售阶段。

## 7.4 deck

显示今日手牌、抽牌堆、弃牌堆、消耗堆、牌库详情入口。今日已抽牌后重复点击不再抽牌。

## 7.5 inventory

显示库存商品，可选择商品用于预览。商品是否可加工 / 可出售由按钮 disabled reason 说明。

## 7.6 process

显示库存、商品详情、基础操作、可用手牌。

## 7.7 cashier

显示商品选择、顾客选择、定价方式、成交确认按钮。

## 7.8 daybook

显示今日摘要与日结确认。日结后锁定当天经营动作。

## 7.9 reward

显示收店奖励。必须日结后开放。

## 7.10 passives

显示店铺被动、货源倾向、牌库详情、奖励道具详情。

# 8. 按钮规则

## 8.1 废弃按钮

以下旧按钮不得作为正式 UI 主流程出现：

```text
进入进货
结束进货
进入抽牌
进入处理
进入出售
返回处理
提交成交单
```

## 8.2 保留按钮

```text
开始新局
买入
选择商品
选择顾客
选择定价
鉴定
洗标
包装
公关
使用卡牌
确认出售
确认日结
选择 / 购买奖励
进入下一天
重新开始
打开 Debug
```

---

# 9. 日结与收店 UI

日结是每日硬边界。

点击账本后：

```text
显示今日成交数、今日利润、事故数、现金变化、信誉变化、剩余库存。
如果今日 0 出售，必须二次确认。
确认日结后，所有当天经营区按钮 disabled，并提示“今日已日结”。
```

收店奖励必须日结后显示。奖励完成后进入下一天或最终报告。

---

# 10. Debug UI

Debug 面板必须继续保留：

```text
固定 seed
固定测试局
复制 AppState / RunState / DayState / DeckState / DealPreview
验收清单
```

Debug 面板可以继续通过 `?debug=1` 显示。

---

# 11. UI 验收标准

```text
1. 主界面是店铺场景，不是阶段页。
2. 玩家通过点击店铺区域完成新闻、进货、接单、抽牌、加工、出售、日结、收店。
3. 新闻、进货、接单、抽牌没有强制顺序。
4. 日结和收店奖励仍是硬边界。
5. 交易预览常驻。
6. 手牌可在底栏或牌盒详情中查看。
7. 所有 disabled 按钮有原因。
8. 隐藏标签和暗风险不被泄露。
9. Debug 面板继续可用。
10. 事故弹窗和最终报告继续可用。
```
