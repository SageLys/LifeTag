# 1. 文档目的

本文档用于把已经确定的系统规则和数据结构转化为第一版 HTML 原型可用的内容配置表。

本文档暂不直接书写 JSON，而是先以 Markdown 表格形式定义完整配置内容。

后续可将本文档中的表格转化为：


# 3. 配置通用要求

## 3.1 ID 命名要求

所有内部引用使用英文 snake_case。

示例：

```text
tag_young
product_young_elite_meat
customer_bigtech_hr
market_elite_fake_scandal
card_low_salary_pitch
passive_black_red_is_red
supply_campus_leftover
pricing_blind_box
accident_major
reward_add_passive_black_red
```

中文只放在：

```text
displayName
description
effectText
flavorText
newsText
accidentText
summaryText
```

## 3.2 数值口径

本文档数值是首版原型验证数值，不是最终平衡数值。

基本尺度：

|数值项|建议尺度|
|---|---|
|普通标签价格|+5 到 +25|
|强偏好标签价格|+20 到 +40|
|负面标签风险|+15 到 +40|
|强雷区风险|+25 到 +50|
|商品基础价|25 到 70|
|商品进价|15 到 60|
|商品基础风险|0 到 25|
|卡牌售价加成|+15 到 +50|
|卡牌风险加成|+5 到 +35|
|风险减免|-10 到 -40|
|店铺被动成本|50 到 90|
|货源倾向成本|30 到 60|

## 3.3 三条流派覆盖要求

所有配置必须服务于至少三条可识别流派：

|流派|核心玩法|
|---|---|
|大厂牛马流|叠加年轻、名校、能加班、低薪接受等职场标签，高价卖给大厂 HR / 创业老板，并处理履历风险|
|稳定相亲流|清洗负面标签，包装稳定、体面、情绪稳定，卖给相亲中介 / 家长委员会，走低事故滚雪球|
|MCN 发疯流|将会发疯、抽象、争议感等负面标签转化为流量价值，卖给短视频 MCN，用小事故换收益|

## 8.2 商品生成说明

每个商品生成时：

```text
1. 根据 ProductTemplate 权重抽取模板；
2. 生成 ProductInstance；
3. 从 hiddenTagPool 中抽取 1 个隐藏标签；
4. 按 darkRiskChance 判定是否带暗风险；
5. 若带暗风险，从 darkRiskPool 中抽取具体暗风险；
6. 生成 cost、basePrice、baseRisk，可先使用模板固定值；
7. 商品初始状态为 candidate；
8. 买入后状态变为 inventory。
```

第一版建议 hiddenTagCount 固定为：

```text
min = 1
max = 1
```

这样方便玩家理解。

第一轮测试重点不是：

```text
每条路线胜率是否完全一致
```

而是：

```text
玩家是否能看懂风险；
玩家是否能形成路线；
玩家是否愿意用现金买成长；
事故是否能复盘；
隐藏标签和暗风险是否制造有效张力。
```

## 21.2 卡牌效果暂用摘要表达

本文档的卡牌、被动、新闻效果以策划摘要形式表达。

下一步写 JSON 时，需要把 effectSummary 转成：

```text
Condition
Effect
Modifier
```

## 21.3 暗风险必须有提示

所有暗风险商品都必须至少显示：

```text
暗风险：存在
```

或：

```text
暗风险：履历类可能 / 人设类可能 / 平台类可能
```

不得出现完全没有提示的随机炸弹。

## 21.4 事故必须确定性结算

配置中可以随机的部分是：

```text
商品生成
隐藏标签抽取
暗风险抽取
顾客生成
市场新闻
抽牌
奖励生成
```

配置中不允许随机的部分是：

```text
事故是否发生
```

事故只能由最终爆雷值和事故等级修正规则决定。
