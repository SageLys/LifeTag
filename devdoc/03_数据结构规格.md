文档编号：03

项目名称：《人生标签交易所：牛马肉铺》HTML 快速验证原型

适用对象：游戏设计者、前端开发者、AI Agent / Codex、测试者。

# 1. 文档目的

本文档用于规定《人生标签交易所：牛马肉铺》HTML 原型的数据结构。

本文档解决以下问题：

1. 每类游戏对象应该有哪些字段；
    
2. 哪些对象是静态配置；
    
3. 哪些对象是运行时状态；
    
4. 对象之间如何引用；
    
5. 卡牌、市场新闻、被动等效果如何用统一结构表达；
    
6. 售价、爆雷、事故拆解如何保存；
    
7. JSON 配置如何避免硬编码；
    
8. 后续如何迁移到 Unity 配置或 ScriptableObject。

# 2. 数据设计原则

## 2.1 静态配置与运行时状态分离

静态配置对象放在 `/data/` 下，由 JSON 定义。

运行时对象由游戏开始后根据静态配置生成，存在内存中的 RunState / DayState / DeckState 中。

### 静态配置示例

```text
TagDef
ProductTemplate
CustomerDef
MarketEventDef
CardDef
ShopPassiveDef
```

### 运行时对象示例

```text
ProductInstance
CustomerOrder
CardInstance
DealPreview
DealResult
AccidentInstance
RunReport
```

## 2.2 内部 ID 使用英文

所有逻辑引用必须使用英文 ID。

正确：

```text
tag_elite_school
customer_bigtech_hr
card_low_salary_pitch
pricing_blind_box
```

错误：

```text
名校
大厂HR
低薪接受话术
盲盒价
```

中文只允许出现在显示字段中：

```text
displayName
description
flavorText
newsText
accidentText
uiText
```

## 2.3 配置对象不得保存运行时状态

错误示例：

```json
{
  "id": "product_young_elite_meat",
  "sold": false,
  "revealed": true
}
```

`ProductTemplate` 不得保存 `sold`、`revealed` 等运行时字段。

运行时字段必须在 `ProductInstance` 中。

## 2.4 效果尽量使用通用结构

卡牌、被动、市场新闻、奖励不应各自写一套完全不同的逻辑字段。

推荐统一使用：

```text
Condition
Effect
Modifier
```

## 2.5 所有计算来源必须可拆解

售价、爆雷、事故必须能输出 breakdown。

因此所有影响价格、风险、事故的对象必须提供：

```text
sourceType
sourceId
displayText
value
operation
```

# 7.2 TagDef

## 作用

定义所有标签的基础价值、风险、类别、是否可洗、是否负面等信息。

## 文件

```text
/data/tags.json
```

## 结构

```json
{
  "id": "tag_elite_school",
  "displayName": "名校",
  "description": "高价值体面标签，但与水货组合时容易翻车。",
  "categories": [
    "education",
    "career",
    "status"
  ],
  "basePrice": 20,
  "baseRisk": 5,
  "isNegative": false,
  "isWashable": false,
  "isVisibleInUI": true,
  "defaultRevealState": "visible",
  "keywords": [
    "履历",
    "教育",
    "大厂"
  ],
  "ui": {
    "colorKey": "blue",
    "icon": "tag_elite_school"
  }
}
```

## 字段说明

|字段|类型|说明|
|---|---|---|
|id|string|标签 ID|
|displayName|string|显示名|
|description|string|标签说明|
|categories|string[]|标签类别|
|basePrice|number|标签基础价格价值|
|baseRisk|number|标签基础爆雷值|
|isNegative|boolean|是否负面标签|
|isWashable|boolean|是否可洗|
|isVisibleInUI|boolean|是否显示|
|defaultRevealState|string|默认揭示状态|
|keywords|string[]|搜索 / 归类用|
|ui|object|UI 辅助信息|

# 10. 数据校验规则

## 10.1 通用校验

所有配置对象必须满足：

```text
id 存在
id 唯一
displayName 存在
引用的 id 必须存在
数值字段不得为 NaN
数组字段默认为 []
对象字段默认为 {}
```

## 10.2 TagDef 校验

```text
basePrice 必须是 number
baseRisk 必须是 number
categories 必须是 string[]
isNegative 必须是 boolean
isWashable 必须是 boolean
```

## 10.3 ProductTemplate 校验

```text
visibleTagIds 中所有 tagId 必须存在
hiddenTagPool 中所有 tagId 必须存在
darkRiskPool 中所有 darkRiskId 必须存在
baseCost >= 0
basePrice >= 0
baseRisk >= 0
spawnWeight >= 0
hiddenTagCount.min <= hiddenTagCount.max
darkRiskChance 在 0 到 1 之间
```

## 10.4 CustomerDef 校验

```text
preferredTags 中所有 tagId 必须存在
tabooTags 中所有 tagId 必须存在
budget > 0
riskTolerance >= 0
spawnWeight >= 0
darkRiskSensitivity 只能使用 DarkRiskCategory 枚举
```

## 10.5 CardDef 校验

```text
cardType 必须有效
actionPointCost >= 0
cashCost >= 0
effects 必须是数组
targetType 必须有效
upgradeTo 如果存在，则必须引用有效 CardDef
```

## 10.6 PricingModeDef 校验

```text
priceMultiplier > 0
riskAdd 可以为负数
conditions 必须可解析
```

## 10.7 RewardTemplate 校验

```text
rewardType 必须有效
cashCost >= 0
payload 必须与 rewardType 匹配
```

# 22. 本文档结论

HTML 原型的数据结构必须服务于三个目标：

```text
可开发
可配置
可复盘
```

因此必须做到：

```text
静态配置与运行时状态分离；
所有对象使用英文 ID 引用；
中文只作为显示文本；
卡牌、被动、新闻、奖励尽量使用 Condition / Effect / Modifier 通用结构；
售价、爆雷、事故必须输出 breakdown；
事故链条必须能追溯来源；
第一版数据量要小，但结构必须能扩展。
```

如果后续迁移到 Unity，本数据结构可以对应为：

```text
JSON 配置
→ ScriptableObject
→ 运行时 Instance
→ UI ViewModel
```

但第一版 HTML 原型阶段不需要提前做 Unity 工程结构。
